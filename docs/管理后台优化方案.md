# 管理后台自由度优化方案

> 日期：2026-10-30 · 范围：`admin.html` + `src/admin.ts` + `server/`
> 目标：把后台从「只能改档案文字」升级为「不碰代码即可运营整个站点」

---

## 一、现状诊断

当前后台（352 行 `admin.ts` + 351 行 `server/index.mjs`）只覆盖了一类对象：**档案记录的增删改查**。具体限制如下：

### 1. 管理对象单一
只有 records 一张表可编辑。以下内容仍需改文件、重新构建部署：

| 内容 | 现状位置 | 运营时需要动的操作 |
|---|---|---|
| 站点名称 / 简介 / 座右铭 | `content/site.json` | 手改 JSON + 重新 build |
| 头像 / 社交链接 / 友链 | `content/site.json` + `public/avatar.jpg` | 替换文件 + 重新 build |
| 个人资料（籍贯 / 现居 / 职业） | `content/site.json` → `profile` | 手改 JSON |
| 背景音乐 | `public/audio/`、`music/` | 拷贝文件 + 改代码 |
| 壁纸 / 3D 模型 / 视觉资源 | `public/assets/` | 拷贝文件 + 改代码 |

### 2. 硬编码约束多，且散落在三处
- 分类列固定为 `["作品", "文章", "资源库"]`，在 `server/index.mjs`、`server/records-db.mjs`、`src/admin.ts` **各写死一份**，想加第四列要改三个文件；
- 每列最多 12 份、全站最少 9 份（`server/index.mjs` 的 POST/DELETE 校验）；
- 档案 ID 强制 `X-NNN` 格式，URL 路由用正则 `X-\d{3}` 匹配；
- 正文 20000 字上限、研究记录至少 1 条，均写死在服务端校验里，无法按场景调整。

### 3. 排序不可控，且 ID 会漂移（最严重的设计问题）
- 后台**没有任何排序入口**，展示顺序只能靠删除重建间接调整；
- 更隐蔽的是：`records-db.mjs` 的 `normalize()` 在**每次写操作后**全表重排并重新分配 `X-001`、`X-002`…… 这意味着编辑一次标题，后续档案的 ID 全部变化，对应的 `/archives/RHINE-LAB-X-NNN.txt` 导出地址和 `public/records/X-NNN.json` 全部失效——外链、搜索引擎索引、读者收藏全部断链。

### 4. 编辑与浏览体验弱
- Markdown 正文无预览，保存后才知道前台渲染效果；
- 无草稿态（虽然 clearance 有 `PENDING REVIEW`，但没有「草稿 → 发布」的工作流语义）；
- 列表只显示 ID/中文名/英文名，无搜索、无筛选、无分页；
- 无批量操作（批量改访问范围、批量移动分类）；
- 无修改历史，改错无法回滚；删除即物理删除。

### 5. 无资产与账号管理
- 无文件上传能力，图片/音频/模型只能走文件系统；
- `users` 表已支持 `admin` / `reader` 两种角色，但没有账号管理界面，创建账号要靠 `npm run admin:create` 命令行；
- 无操作日志，无法追溯「谁在什么时间改了什么」。

## 二、优化方案（按优先级分三期）

### P0 · 放开约束 + 稳定 ID + 编辑器增强（地基，约 2~3 天）

**1. ID 稳定化 —— 最高优先级**
- records 表新增 `slug` 列（创建时可自定义，默认 `X-NNN`），作为永久标识；
- `normalize()` 改为只维护 `sort` 字段，**不再重编号**；
- URL 路由从 `X-\d{3}` 放宽为 `[A-Za-z0-9-]+`，TXT 导出与 records JSON 按 slug 寻址；
- 迁移：现有数据 slug 落为当前 ID，一次性完成，旧 TXT 地址保留重定向。

**2. 约束可配置化**
- 三处硬编码的 `COLUMNS` 收敛为数据库 `settings` 表中的 `categories` 配置，后台可增删改分类、调整顺序；
- 「每列上限」「总量下限」「正文字数上限」改为 settings 中的数值项，默认维持现状（12 / 9 / 20000），可调整为 0（不限）。

**3. 拖拽排序**
- 列表行支持拖拽（HTML5 DnD 即可，无新依赖），松手后 `PUT /api/records/:id/sort` 持久化，只改 sort 不碰 ID。

**4. 编辑器增强**
- Markdown 正文改为「编辑 / 预览」分屏切换，复用前台 `markdown.ts` 渲染管线，保证所见即所得；
- 新增「前台预览」按钮：以当前表单内容临时渲染详情页样式（前端本地渲染，不落库）；
- 表单状态本地自动暂存（sessionStorage），防止误关页面丢稿；
- clearance 为 `PENDING REVIEW` 时在列表上加「草稿」徽标，形成最小可用的草稿/发布流。

### P1 · 站点设置 + 媒体库（覆盖日常运营，约 3~4 天）

**5. 站点设置面板**（新标签页「站点」）
- 可视化编辑 `site.json` 全量字段：站点名、简介、座右铭、资料卡、社交链接、友链（友链做成与 records 链接相同的行编辑器）；
- 保存即写 `content/site.json` 并同步快照，无需重新构建（构建时已 `no-store` 拉取的字段即时生效，其余提示「下次构建生效」）；
- 头像上传：裁剪为正方形 → 写 `public/avatar.jpg`，前端带缓存破坏参数。

**6. 媒体库**（新标签页「媒体」）
- 上传图片 / 音频 / GLB 到 `public/assets/uploads/`，服务端校验类型与大小（图片 ≤ 5MB、音频 ≤ 20MB、模型 ≤ 50MB）；
- 列表展示缩略图、尺寸、引用计数；未引用文件可安全删除；
- 编辑器中「插入图片」按钮：从媒体库选择，自动插入 Markdown 图片语法。

**7. 列表增强**
- 顶部搜索框（匹配标题 / en / abstract），筛选器（分类、clearance），前端过滤即可，数据量小无需服务端分页；
- 行内批量勾选：批量修改 clearance、批量移动分类、批量删除（进回收站，见 P2）。

### P2 · 历史、账号与系统（治理层，约 3 天）

**8. 版本历史 + 回收站**
- 新增 `record_revisions` 表：每次 PUT 前快照旧值（记录 ID、修改人、时间、全量 JSON）；
- 记录详情页提供「历史」侧栏，可 diff 查看与一键回滚；
- 删除改为软删除（`deleted_at` 字段），回收站 30 天内可恢复，超期清理。

**9. 账号与审计**
- 「账号」标签页：管理员列表、新建/停用账号、重置密码、修改角色（admin/reader）；
- `audit_log` 表记录所有写操作：操作人、动作、对象、时间、摘要；「系统」标签页可查。

**10. 备份与恢复**
- 一键导出全量 JSON（records + settings + users 摘要），下载存档；
- 导入时整包校验后事务写入，失败整体回滚（沿用 `mutateAndSync` 的事务模式）。

## 三、技术路线

**后端**：继续零依赖 Node HTTP（不引 Express），在 `server/index.mjs` 增加路由模块：

```
/api/settings    GET/PUT          站点配置（site.json + 可调约束）
/api/assets      GET/POST/DELETE  媒体库（multipart 上传）
/api/records/:id/sort      PUT    排序
/api/records/:id/revisions GET    历史
/api/trash       GET/POST/DELETE  回收站
/api/users       GET/POST/PUT     账号管理（仅 admin）
/api/audit       GET              操作日志
/api/backup      GET/POST         导出 / 导入
```

上传接口需要手写 multipart 解析（约 60 行）或将请求体限制放宽到 50MB 后用 Base64 JSON——建议前者，避免内存翻倍。

**数据库**：新增 `settings`、`assets`、`record_revisions`、`audit_log` 四张表，沿用 better-sqlite3 事务 + 快照回写模式。

**前端**：`admin.ts` 按标签页拆模块（`admin/` 目录：records.ts / site.ts / media.ts / users.ts / system.ts），保留现有纯 DOM 风格与 `admin.css` 设计语言，不引框架。顶栏导航从「查看首页 + 退出」扩展为标签栏。

**兼容性**：所有 P0 变更附带一次性迁移脚本；旧 `X-NNN` URL 301 到新 slug 地址，保证外链不断。

## 四、里程碑建议

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| M1（P0） | ID 稳定化、可配置分类/约束、拖拽排序、Markdown 预览 | 编辑标题后所有 URL 不变；不改代码新增分类列 |
| M2（P1） | 站点设置、媒体库、列表搜索/批量 | 换头像、改简介、传图发文全程不碰文件系统 |
| M3（P2） | 历史回滚、回收站、账号管理、审计、备份 | 误删可恢复；任何变更可追溯 |

每期独立可交付、可回滚，互不强依赖。
